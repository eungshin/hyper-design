# 캔버스 개선 요청 — 실사용 추적에서 나온 것

캔버스를 고치는 세션(/re 트랙 `canvas-edit`)이 읽는 목록. 근거는 각 세션 폴더의 `log.md` 마찰 표(F 코드)와 `rounds.jsonl`.
이미 백로그에 같은 항목이 있으면 새 일을 만들지 않고 그 번호에 근거만 더한다.

## R1. 보낸 메모에 "반영됨" 표시 (2026-10-23, Master 요청)

- **요청:** 보낸 메모 중 실제로 구현된 것은 캔버스에서 한눈에 "구현 완료"로 보여야 한다. 지금은 보낸 뒤 반영됐는지 사람이 화면을 하나씩 열어 비교해야 한다.
- **백로그:** canvas-edit #231(`hd reply --kind 반영됨|답변|질문|보류` + 메모 목록 상태 칩 + 패널 거르기)이 같은 것. #228(상태 파일)의 메모 상태 `작성 중 → 보냄 → 반영됨`이 그 바탕.
- **이번 실사용에서 더해진 조건:**
  1. **부분 반영**이 있다. 한 메모 안 요청 둘 중 하나만 된 경우(로그인: 이메일 칸 done, 가운데 정렬은 그 뒤에)가 10건 중 3건. `반영됨`과 `보류` 사이에 "일부 — 남은 것 한 줄"이 필요하다.
  2. **보류는 이유와 함께 그 자리에서** 보여야 한다. AI가 예시 사전 제거를 "다음 조각"으로 미루고 끝 보고에만 적었더니, 사람은 미반영으로 읽고 다시 지적했다(F12). 보류 칩 + 이유 한 줄이 있었으면 왕복 하나가 없었다.
  3. **결정으로 바뀐 메모**(다른 화면에 합침, 거절)도 상태가 필요하다. 질문창 빈 레이아웃은 "기존 화면에 합침"으로 결정됐지만 카드엔 아무 표시가 없어 사람이 "왜 아직 비었나"를 물었다(F13). → `답변`이나 `보류`가 아니라 "대체됨 — 어디로" 한 줄.
  4. 반영 표시는 AI가 화면 파일을 고친 뒤에 붙인다. 붙인 근거(고친 화면 id, 캡처 확인 여부)를 칩 툴팁에 남기면 사람이 믿고 넘어간다.
- **근거:** `2026-10-23-dayfine-onboarding/log.md` F1·F2·F12·F13, `rounds.jsonl` round 4 item 1·7·8·9·10.

## R2. 빈 레이아웃은 만들 때 화면 파일로 (F13)

- 빈 레이아웃 카드는 브라우저에만 있고 `screens.json`·`screens/` 에 없다. AI가 채우려면 화면을 새로 만들어 등록해야 한다. #228 상태 파일에 실리면 AI가 적어도 읽을 수는 있다 — 그 단계에서 빈 레이아웃의 이름·목적이 상태 파일에 들어가는지 확인.

## R3. 정본 → PRD → spec 연쇄 (F5·F10)

- PRD를 고치면 `spec_inventory.json` quote가 낡아 selfcheck가 막는다. PRD 갱신과 quote 갱신이 한 명령이면 손 수정이 없어진다. 캔버스 범위 밖(하네스 `scripts/`)일 수 있음 — 판단은 그 세션이.
