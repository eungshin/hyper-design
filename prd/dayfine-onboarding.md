# Dayfine — 로그인 이후 첫 실행 온보딩

## 표면

- **데스크톱 앱 창, 단계 마법사(wizard).** 모바일 화면이 아니다. 창 크기 1080×680 기준, 최소 900×600.
- 한 화면에 할 일 하나. 위에 작은 단계 머리(로그인 › 설정 › 체험 › 시작, 지금 묶음만 강조), 큰 제목 한 줄 = 할 일, 그보다 작은 보조 줄, 아래에 보조(테두리) 버튼 "이전으로" + 주 실행(채운 알약) "다음으로".
- 체험 화면은 좌우 분할: 왼쪽 = 직접 해 보는 곳(예문·화면), 오른쪽 = 큰 키 그림 + 짧은 설명 + "키 바꾸기".
- 결과물은 캔버스 하나(모든 단계를 한 판에, 갈래 화살표, 주석).
- 움직이는 그라데이션: 앱에서는 온보딩 전 화면에 같은 움직임. 캔버스에서는 멈춘 그림이 기본이고, 로그인 화면을 누르면 예시로 움직인다(OS의 움직임 줄이기 설정이면 멈춤).
- **테마(사용자 지정 레퍼런스):** 테마 파일 `foundation/themes/dayfine-dawn.json`(setup_out `--theme dayfine-dawn.json`). Dayfine 새벽(dawn) 그라데이션. 창 바탕 `linear-gradient(120deg, #fafafa 15%, (#72c1ea 24% + 흰색) 55%, (#fbbf24 19% + 흰색) 100%)`, 읽기 면 #ffffff, 글자 #1b1b1b, 보조 #5d5d5d·#737373, 선 #dedede, 주 버튼 먹색 #1b1b1b, 강조 #0f7ec2, 예문 강조 노랑 #f5c518. 팔레트 라이브러리에서 고르지 않는다.
- **비율(기존 온보딩 목업):** 제목 32/40 굵기 650, 질문 18/24 650, 보조 16/24, 단계 머리 15, 키 힌트 13, 모서리 12·16, 버튼 알약.
- **레이아웃:** Typeless식 좌우 분할 55:45. 왼쪽 흰 읽기 면에 할 일, 오른쪽 그라데이션 바탕 위 흰 카드에 동작 그림. 승인 샘플 `runs/dayfine-onboarding-sample/index.html`(직업 1장, 체험 1장)을 그대로 따른다.
- **보이스:** `haeyo` 프리셋(담백한 해요체). 줄표 금지, 경어 '-시-' 최소, 확인 질문엔 대답형 버튼("네, 계속" / "아니요, 키 바꾸기").

## 제품

Dayfine은 Windows 트레이 앱이다(Mac 예정). 어떤 프로그램에서든 단어나 문장을 선택하고 **Ctrl+C를 두 번** 누르면 작은 창(Popup)에 뜻·발음·예문·AI 설명이 뜬다. 이미지·영상 위 글자는 **Ctrl+Shift+X**로 화면을 잡아 OCR로 찾는다. **Shift+Space**로 질문창을 열어 사전·AI·웹에 바로 묻는다. Mac에서는 Ctrl 대신 ⌘로 표기한다.

## 이 온보딩이 푸는 갈등

설치한 사람은 설명을 읽고 넘기지 않는다. 지금 튜토리얼은 가짜 무대에서 커서 시연만 보여 주고 끝나서, 사용자가 실제로 아무 프로그램에서 Ctrl+C 두 번으로 Popup이 뜨는 경험을 하지 못한 채 나간다. 길면 중간에 나간다.

**운영자 쪽 갈등:** Google 로그인은 이메일과 이름만 준다. 마케팅을 할 때 어떤 직업군이 광고에 반응해 설치하고, 어떤 직업군이 결제까지 가는지 숫자로 알 수 없다. 온보딩이 Identity의 빈칸(직업, 목적)과 자기 응답 Attribution(알게 된 경로)을 채워야 한다.

## 사람

- **대학원생·연구원** — 영어 논문 PDF를 읽다가 단어를 복사해 브라우저 사전 탭에 붙여 넣는 일이 귀찮다. 성공한 순간: PDF에서 Ctrl+C 두 번으로 바로 뜻이 뜬다.
- **해외 업무 직장인** — 영문 메일과 계약서를 쓴다. 정확한 쓰임과 예문이 궁금하다. 성공한 순간: 메일 속 표현을 바로 찾고 예문을 본다.
- **어학 시험 준비생** — 토익·JLPT 지문을 읽는다. 발음과 뜻을 함께 보고 싶다.

## 흐름

```
로그인 ─(signed_in)─▶ needs_onboarding?
                       ├─ false → 바로 사용(온보딩 없음, 창 닫힘)
                       └─ true  → 직업 → 배울 언어 → 쓰는 방향
                                   → 체험: 사전 세팅 배우기 → 복사로 찾기 → 화면에서 찾기 → 질문창 → 질문창 쓰는 법
                                   → 알게 된 경로 → 시작
```

통과한 단계는 다시 잠기지 않는다. 중간에 끄면 다음 로그인 때 마지막 단계에서 이어 한다(`needs_onboarding`은 완료 기록 전까지 true).

## 화면별 요구

### 1. 로그인 (단계 머리: 로그인)

- 로고, 한 줄 가치 문장, **공식 Google 버튼**(G 로고, "Google로 계속하기" — 색만 바꾼 자체 버튼 금지).
- 버튼 바로 아래 **선택 체크 하나**: "할인 쿠폰과 새 기능 소식을 이메일로 받기 (선택)". **처음엔 체크 해제.** 체크와 무관하게 로그인은 똑같이 된다. 혜택을 앞세운 강한 문구로.
- 그 아래 작은 글: "계속하면 이용약관과 개인정보처리방침에 동의합니다." (두 문서는 링크). **나이 문구는 넣지 않는다.**
- **이메일 로그인도 둔다**(2026-10-23, 지원 예정): Google 버튼 아래 "또는" 구분선 + 이메일 입력칸 + "이메일로 계속하기". 게스트 버튼 없음.
- 로고·문장·버튼·체크·약관 줄은 왼쪽 읽기 면 안에서 가로 가운데 정렬로 맞춘다.
- 상태(`auth.state`):
  - `signed_out` — 위 기본 화면
  - `signing_in` — "브라우저에서 로그인을 마쳐 주세요", 대기 표시, **취소** 버튼, "브라우저 다시 열기" 링크. Google 화면은 앱 안에 띄우지 않는다(시스템 브라우저).
  - `signed_in` — 잠깐 성공 표시(이름 또는 이메일, 긴 이메일은 한 줄 말줄임) 후 다음으로
  - `reauth_required` — "다시 로그인해 주세요" + 직전 계정 이메일 + Google 버튼
  - `error` — 코드별 문구 + 다시 시도, Google 버튼은 계속 보임:
    - timeout: "시간이 지나 로그인이 취소됐습니다. 다시 시도해 주세요"
    - offline: "인터넷 연결을 확인해 주세요"
    - unavailable: "로그인을 잠시 사용할 수 없습니다. 잠시 후 다시 시도해 주세요"
    - email_unverified: "Google 계정의 이메일 인증을 마친 뒤 다시 시도해 주세요"
    - unknown: "로그인에 실패했습니다. 다시 시도해 주세요"
    - cancelled: 조용히 기본 화면으로
- 첫 로그인 때만 한 줄: "이 PC의 기존 조회 기록을 이 계정에 연결했습니다."

### 2. 직업 (설정 1/3) — 필수
- 제목은 정보를 주어로: "하는 일이 무엇인가요?" 보조 줄: "하는 일에 맞는 사전을 다음 단계에서 골라 드릴게요."
- **하나만 고른다. 건너뛰기 없음. "말하고 싶지 않음" 없음.** 목록에 없으면 **직접 입력**.
- 목록(순서 고정, 3×3 아이콘 타일, 숫자키 1–9):
  1. 대학생
  2. 대학원생·연구원
  3. 어학 시험 준비
  4. 개발자·엔지니어
  5. 해외 업무 직장인
  6. 의료·약학·바이오
  7. 번역·콘텐츠 제작
  8. 교사·강사
  9. 직접 입력(짧은 입력칸)
- 오른쪽 카드: 고른 직업의 큰 아이콘 + 한 줄("논문을 읽을 때 필요한 사전을 먼저 보여 드릴게요"). 점수·사전 목록은 보이지 않는다.
- 골라야 "다음"이 열린다. 아이콘은 설정 화면에만.

### 3. 배울 언어 (설정 2/3)
- 모국어(기본: 시스템 언어)와 배울 언어(기본: 영어)를 고른다.
- 배울 언어 목록 = 앱이 실제로 주는 42개 언어(제 이름 표기, en·ko·ja·zh 먼저, 나머지는 이름순): English, 한국어, 日本語, 中文, Bahasa Indonesia, Dansk, Deutsch, Español, Filipino, Français, Hrvatski, Italiano, Kiswahili, Magyar, Nederlands, Norsk, Oʻzbekcha, Polski, Português, Română, Shqip, Suomi, Svenska, Tiếng Việt, Türkçe, Čeština, Ελληνικά, Монгол, Русский, Українська, Қазақша, עברית, اردو, العربية, فارسی, नेपाली, हिन्दी, ไทย, ລາວ, မြန်မာ 외(전체는 dictionary `ui_host/popup/src/shared/languages.js`).
- 위에 **검색칸**(이름 일부로 거름), 아래 **스크롤 목록**(고른 줄 강조). 목록에 없으면 "찾는 언어가 없나요? 직접 입력" — 지원한다고 보이지 않고 요청으로만 받는다.

### 4. 쓰는 방향 (설정 3/3) — 필수, 여러 개
- "주로 어디에 쓰나요?" 여러 개 고를 수 있다(최소 1개).
- 쓰임: 학습 / 업무 / 전공·논문 / 일상 회화. 취향: 예문 / AI에게 묻기 / 발음 / 그림.
- 쓰임과 취향은 같은 화면의 두 줄 묶음. 이 화면에도 추천 점수·사전 목록은 보이지 않는다(기록만, 결정 #434).

### 5. 사전 세팅 배우기 (체험 0) — 학습형
- 직업 + 배울 언어 + 쓰는 방향으로 고른 **추천 칸 5~8개**가 **실제 Popup 탭 줄 부품**으로 놓여 있고(캔버스에서는 디지털 트윈 캡처 자리, 자체 그림 금지), 사용자가 **직접 세팅하는 법을 해 보며 배운다**: 칸 하나 끄기/켜기, 끌어서 순서 바꾸기(첫 칸 = 기본으로 열리는 사전), 칸 더하기.
- 칸 종류: 오프라인 사전(영한·영영), Wiktionary, AI 사전, 웹 사전 사이트(Popup 안 웹 칸), 웹 검색, 백과, 그림.
- 예: 대학원생·연구원 + 전공·논문 + AI → 영한, AI 설명, 학술 백과, 웹 검색. 해외 업무 직장인 + 업무 + 예문 → 영한, 예문, AI 사전, 웹 검색.
- AI 웹 칸은 하나만 켠다. "나중에 설정에서 바꿀 수 있어요" 한 줄.
- 통과: 한 번이라도 순서를 바꾸거나 칸을 켜고 끈 뒤 "네, 계속". 오른쪽 카드는 지금 세팅으로 보일 Popup 탭 줄 미리보기.

### 6~8. 체험 (체험) — 실제로 해 봐야 다음이 열린다

공통: 큰 제목 = 할 일, 작은 줄 = 키(키캡), 확인 질문, 오른쪽 = 큰 키 그림, "키 바꾸기". 이 화면들에는 이모지를 두지 않는다.

- **6. 복사로 찾기** — 예문 속 단어를 선택하고 Ctrl+C 두 번. 진짜 Popup이 그 단어 뜻으로 떠야 통과. 확인 질문 예: "작은 창에 뜻이 떴나요?" 오른쪽 키 그림은 누르는 키마다 그 키캡이 켜진다(Ctrl 누름 → C 첫 번째 → C 두 번째). **예시 사전 탭·예시 뜻은 그리지 않는다** — 뜨는 것은 진짜 Popup(캔버스에서는 트윈 캡처 자리).
- **7. 화면에서 찾기** — 이미지 속 글자에서 Ctrl+Shift+X로 영역을 잡고 단어를 누른다. 결과가 떠야 통과.
- **8. 질문창** — Shift+Space로 질문창을 열고 질문 하나를 보낸다. 답이 뜨면 통과. 이어서 다음 화면 '질문창 쓰는 법'(읽고 넘기는 안내): `/`로 보낼 곳 고르기, Enter 보내기·Shift+Enter 줄바꿈·Esc 닫기, 저장한 대화에 `/` + 이름 + Tab으로 이어 묻기(방법만, 해 보게 하지 않음).
- 실패 상태: 다른 키를 눌렀을 때("Ctrl을 누른 채 C를 빠르게 두 번 눌러 주세요"), 일정 시간 아무 일 없음(도움말 한 줄 + 다시 해 보기), 키 충돌(다른 프로그램이 쓰는 키 → 키 바꾸기 안내).

### 9. 알게 된 경로 (시작) — 필수, 하나만

- 첫 성공 뒤에 묻는다. "Dayfine을 어디서 알게 됐나요?"
- 인스타그램·페이스북 / 유튜브 / 구글 검색 / 블로그·커뮤니티 / 지인 추천 / 학교·회사 / 직접 입력.
- 광고 캠페인 꼬리표(UTM)는 설치 링크에서 따로 받는다(화면에는 보이지 않음). 이 질문은 그것을 보완한다.

### 10. 시작 (시작)

- "이제 쓸 수 있어요" + 지금 3일 동안 프로처럼 찾기·OCR·질문창을 제한 없이 쓴다는 한 줄. 3일 뒤 무료 한도. 결제 화면은 만들지 않는다.
- 마지막에 온보딩 완료를 기록한다(`auth_complete_onboarding()`). 오프라인이면 앱이 기억했다가 보낸다.
- 고정·나누기·발음 선택은 넣지 않는다. 첫 Popup 위에 한 줄로 알려 준다.

## 수집 데이터(분석용)

계정 id 하나에 붙는다: 직업(목록 값 또는 원문+서버 분류), 쓰는 방향(쓰임·취향), 배울 언어, 알게 된 경로(+UTM), 마케팅 수신 동의(시각), 온보딩 단계 도달·완료 시각. 운영자는 직업별로 광고 → 설치 → 가입 → 첫 성공 → 결제 깔때기를 본다.

## 지킬 것

- 화면 문구에 "Ctrl"을 박지 않는다는 원칙은 실제 앱 구현에서 키 표기 함수로 처리한다(이 디자인에서는 Windows 표기로 보여 준다).
- 긴 이메일·한중일 이름: 한 줄 말줄임. 버튼 문구는 긴 언어에서도 두 줄로 깨지지 않게.
- 결제·가격 화면, 설문 추가 항목(영어 실력 등)은 범위 밖.

## 참고 제품(관례)

- **Typeless(데스크톱 받아쓰기 앱):** 실제 단축키로 실제 결과가 나와야 다음. 단계 머리 3묶음, 큰 제목=할 일, 키캡 보조 줄, 확인 질문, 오른쪽 큰 키 그림, 아래 두 버튼. 끄면 이어 하기.
- **Smooth AI(데스크톱 회의 통역):** 로그인 화면 Google 버튼 아래 선택 체크 "Get updates on special offers and coupons (optional)" + 약관 한 줄. 가치 한 문장 화면(큰 제목, 숫자 하나만 강조색, 출처 작게). 마스코트 말풍선이 "왜 묻는지" 먼저 말한 뒤 이모지 직무 목록 + 자유 입력.
