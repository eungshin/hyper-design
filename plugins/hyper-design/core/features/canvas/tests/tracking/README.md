# 검토 과정 기록 — 과한 검토가 구현을 느리게 하는 곳 찾기

| 파일 | 누가 쓰나 | 무엇 |
|---|---|---|
| `runs.json` | `tests/conftest.py` 가 테스트를 돌릴 때마다 자동으로(git 에 넣지 않음) | 언제 · 범위(unit/part/full) · 고른 것(`-m`·`-k`·`--lf`) · 통과/실패 이름 · 걸린 초 |
| `process.json` | 조각을 커밋하는 세션이 한 항목 | 테스트 시간·전체 실행 수 · 게이트 걸림(규칙·진짜/잡음·대응 분) · 잡은 버그(새 테스트/전체) · 낭비와 고칠 점 · `policy` 한도 |
| `review.py` | 번호 조각 끝, 또는 느리다고 느낄 때 | 두 파일을 읽어 한도를 넘은 곳과 고칠 후보를 보인다(약 1초) |

자가 개선: `review.py` 가 짚은 곳은 고칠 점을 `process.json` 그 조각의 `waste[].fix` 에 적고, 규칙이면 `contract.md` '테스트 층'·'책임 게이트' 나 `policy` 를 바로 고친다. 고친 뒤 다음 조각에서 같은 걸림이 사라졌는지 다시 본다. `policy.review_after_slice` 조각이 끝나면 게이트 규칙마다 남길지 정한다.
