# protocol v1 (draft) = today's HTTP shape

Locked by task 47-1 before 47-2 merges the hub and the helper into one server. `helper.json` (canvas `helper.py`) and `hub.json` (`hd home` → `home/home_server.py`) list every route: method, path, auth, callers, request, response, and the cases replayed in order by `test_protocol_v1.py`. That test starts real child processes on free ports, with a temp HD_HOME, USERPROFILE and HOME and a fake paseo. It checks the status and the response keys and types, not the values. Run it with `python -m pytest plugins/hyper-design/core/features/canvas/tests/protocol` (marked `slow`, about 20 s, most of it rebuilds after apply, restore and delete).

Shape language (`expect.json`): `"str" "int" "num" "bool" "null" "list" "dict" "any"`, unions joined with `|` · `{key: shape}` = object that has these keys (extra keys allowed; `key?` = optional) · `{"$eq": v}` = this exact value · `{"$list": shape, "$min": n}` = every element · `{"$map": shape}` = every value. `expect.status` may be `"dropped"` (connection closed without a reply). `expect.ctype` / `contains` check non-JSON bodies. `request.token` = `false` (none) or a wrong string, `host` overrides Host, `raw` = literal body, `size` = N bytes of junk, `${name}` = a value saved by an earlier case (`save`). A case with `skip` documents a route that is not replayed (native dialog, spawns a build) and names the test that covers it. Cases named `SUSPECTED BUG` record today's behaviour as is. Fix the bug and that case's expectation in the same change.

## events (task 47-4a) — `events.json`

The contract for `project.events()` (SDK, 47-3) and the canvas EventSource (47-4b): SSE route `GET /v1/p/<name>/events` (and the old root `GET /api/events` with the session token; the stand-alone helper serves `/api/events` too), the event types and their shapes, Last-Event-ID resume with a bounded ring and a `reset` frame, the heartbeat, and the async apply opt-in (`"async": true` on `POST /api/apply`). Read the prose keys at the top of the file first. `test_protocol_events.py` replays the `routes` cases and the `flows` in-process (real hub on a temp HD_HOME, fake build) — `stream` expectations read the first frames of the stream (`retry`, then `events` in order, checked against `event` + `types`), `flows` script several requests and streams together.

## presence (task 47-5a) — `presence.json`

Agent presence and sending: `POST /v1/p/<name>/hello` (register or refresh, returns a lease), `/beat`, `/bye`, `/progress`, `GET /v1/p/<name>/agents`, `POST /v1/p/<name>/agents/spawn` (off unless `HD_ALLOW_SPAWN=1`), the old root aliases `/api/hello` · `/api/beat` · `/api/progress` · `/api/bye` · `/api/presence` · `/api/agents/spawn`, `connected` on `GET /api/agents`, and `POST /api/forward {text, to?, notes?}` choosing between an event to a connected agent and the AgentAdapter (paseo · claude · none). Read the prose keys at the top. The new event types (`agent.hello` · `agent.away` · `agent.progress` · `agent.reply` · `request.sent`) are in `events.json` `types`. `test_protocol_presence.py` replays the routes in one session in order (later cases see agents made by earlier ones) and each flow on a fresh session, with the hub and stream helpers of `test_protocol_events.py`.
